> 版本：V0.5（2026-05-09）
> 阶段：第一阶段（M2 实施目标）
> 立场：以"真实记录每一笔库存动作"为核心，配合 restaurant 出餐链路打通真实数据采集

## 1. 业务定位

库存系统是阿堡平台"**7 大经营动作-物在流转**"的核心承载。

在餐饮经营中，"物"（原料 → 半成品 → 成品）的流转是成本结构的物理基础。每一份出餐都消耗了具体的原料，每一次采购都补充了库存水位，每一次损耗都侵蚀利润。**没有真实的库存数据，所有"降本增效"都是空谈。**

库存系统在阿堡平台中的位置：

```
原料采购 → 验收入库 → 库存持有 → 半成品制作（消耗原料 / 产出半成品）
                                         ↓
                                    成品出库 → 出餐扣减 → 顾客
                                         ↓
                                    盘点 / 损耗 / 调拨（库存修正的合法途径）
```

与 restaurant 模块的关系：restaurant 负责"订单→出餐"的流转，库存系统负责"原料→半成品→成品"的流转。**两个系统在"出餐扣减"点交汇。**

## 2. 业务场景（5 个核心场景）

### 场景 1：原料采购入库

**完整流程**：

```
采购计划 → 生成采购单 → 供应商发货 → 到货验收 → 入库登记 → 库存增加
```

**涉及角色**：采购员（发起）、验收员（验收）、库管员（入库确认）

**必须真实记录的数据**：

| 数据项 | 说明 | 是否必填 |
|--------|------|---------|
| 供应商 | 哪个供应商供货 | 是 |
| 原料 SKU | 采购了什么原料 | 是 |
| 批次号 | 供应商批次 / 生产日期批次 | 是 |
| 保质期 | 到期日期 | 是（如有） |
| 数量 | 采购数量 + 实际验收数量 | 是 |
| 单价 | 采购单价 | 是 |
| 验收人 | 谁验收的 | 是 |
| 验收照片 | 到货状态拍照 | 推荐 |
| 入库时间 | 精确到秒 | 是 |
| 采购单号 | 关联采购单 | 是 |

**异常情况**：
- 质量不合格 → 拒收，记录原因 + 拍照，生成退货单
- 数量不符 → 按实际验收数量入库，记录差异，生成差异报告
- 票据缺失 → 可先入库，标记"票据待补"，后续补票
- 保质期过短 → 可接收但标记"临期"，触发优先使用提醒

### 场景 2：半成品制作（厨房上游）

**完整流程**：

```
原料出库（领料）→ 加工制作 → 半成品入库
                      ↓
                 损耗自动计算 = 领料量 - 半成品理论产出量
```

**核心逻辑**：每制作一批半成品，系统自动计算：
- 理论原料用量（BOM 配方 × 半成品数量）
- 实际原料用量（领料出库数量）
- 损耗量 = 实际 - 理论
- 损耗率 = 损耗量 / 实际用量

**涉及角色**：厨房负责人（领料 + 制作登记）

**必须真实记录的数据**：
- 投入原料清单（SKU + 批次 + 数量）
- 产出半成品（SKU + 批次 + 数量）
- 制作人 + 制作时间
- 损耗量（自动计算）
- 损耗原因（如有异常损耗）

**异常情况**：
- 损耗异常偏高 → 标记 + 通知店长审查
- 原料批次不同混用 → 记录混用批次
- 制作失败 → 全部损耗，记录原因

### 场景 3：出餐扣减库存

**与 restaurant 模块的对接点**：

```
顾客下单 → KDS 显示订单 → 厨师开始制作 → KDS 完成出餐
                                              ↓
                                    触发库存扣减（半成品 -1）
```

**关键设计问题**（详见第 4 章）：

| 问题 | 选项 | 推荐 |
|------|------|------|
| 何时扣库存？ | A. 下单时扣 / B. KDS 完成时扣 / C. 支付成功时扣 | **B（KDS 完成时扣）** — 最接近真实消耗 |
| 库存不足怎么办？ | A. 阻断下单 / B. 告警但允许下单 / C. 不阻断 | **B（告警但允许）** — 库存数据初期不准，不能因数据问题阻断营业 |
| 退单怎么回滚？ | A. 自动回滚 / B. 人工确认回滚 / C. 不回滚 | **A（自动回滚）** — 但记录退单原因 |
| 并发扣减怎么处理？ | 乐观锁（CAS） | yudao MES 已有 `updateMaterialStockQuantity(id, quantity, checkFlag)` |

**异常情况**：
- 库存不足 → 告警 + 标记"负库存"，允许继续出餐
- 并发扣减 → 乐观锁重试，失败则排队
- 网络断开 → KDS 本地缓存出餐记录，网络恢复后补扣

### 场景 4：盘点

**盘点类型**：

| 类型 | 频率 | 范围 | 是否停业 |
|------|------|------|---------|
| 日盘 | 每日 | 关键原料（高价值 / 易损耗） | 否 |
| 周盘 | 每周 | 全部原料 + 半成品 | 否（营业结束后） |
| 月盘 | 每月 | 全部库存（含固定资产） | 建议停业半天 |

**盘点流程**：

```
创建盘点方案 → 生成盘点任务 → 冻结库存（可选）→ 实物盘点 → 录入实盘数 → 生成差异报告 → 审核 → 库存调整
```

**盘盈盘亏处理**：
- 盘盈 → 库存增加，记录原因（如"上次盘点漏记"）
- 盘亏 → 库存减少，强制记录原因（如"过期报废未登记"、"操作损耗"）
- 超出阈值 → 必须店长审核，不能直接过

**yudao 已有能力**：MES `wm_stock_taking_plan/task/line/result` 已完整支持方案→任务→结果闭环，含盲盘、冻结盘点。

### 场景 5：损耗 / 报废

**三类损耗**：

| 类型 | 触发条件 | 处理方式 |
|------|---------|---------|
| 过期损耗 | 保质期到期 | 系统自动标记"临期"（到期前 N 天），到期当天生成损耗单 |
| 变质损耗 | 存储不当导致 | 人工登记，强制拍照 + 原因 |
| 操作损耗 | 制作过程中的正常/异常损耗 | 半成品制作时自动计算（场景 2） |

**损耗登记必须包含**：
- 损耗类型（过期/变质/操作失误/其他）
- 原料 SKU + 批次 + 数量
- 责任人
- 原因说明
- 照片（变质/操作失误必须）
- 审批人（超出阈值时）

## 3. 与 yudao 已有模块的关系

> 详细盘点见 [yudao 已有库存能力盘点](./m1-track-c-yudao-capability-audit.md)

### 3.1 核心决策：基于 MES wm 构建，而非 ERP

| 维度 | ERP | MES wm | 决策 |
|------|-----|--------|------|
| 仓库模型 | 单层 | 仓库→库区→库位 三级 + XYZ | **用 MES** |
| 批次管理 | 无 | 完整生命周期 | **用 MES** |
| 序列号 | 无 | 有 | **用 MES** |
| 盘点 | 简单单据 | 方案→任务→结果闭环 | **用 MES** |
| 库存台账 | 仅 productId+warehouseId+count | 物料+批次+仓库+库区+库位+供应商 | **用 MES** |
| 库存流水 | 简单出入库记录 | 完整事务审计（含关联事务 ID） | **用 MES** |

**结论**：MES 的 wm 子模块（23 个子模块）是一个完整的 WMS。对于阿堡"进销存+生产"场景，**优先基于 MES wm 构建库存能力**。

## 4. 与 restaurant 模块的对接

### 4.1 库存扣减时点

```
顾客扫码点餐 → 提交订单 → 支付成功 → KDS 显示 → 厨师制作 → KDS 完成出餐
                                                                    ↓
                                                           🔴 库存扣减在这里
```

**推荐：KDS 完成出餐时扣减库存**。

理由：
- 最接近真实物料消耗的时间点
- 下单→出餐之间可能发生退单，提前扣减会产生"幽灵库存"
- KDS 完成出餐已经有操作记录（KdsController.finishItem），扣减库存可作为其副作用

### 4.2 对接流程

```
┌──────────────────────┐         ┌──────────────────────┐
│  Restaurant 模块      │         │  库存系统             │
│                      │         │                      │
│  KDS.finishItem()    │──①──→  │  扣减半成品库存        │
│                      │         │  - 查 BOM 配方         │
│                      │         │  - 扣原料理论用量       │
│                      │         │  - 记录消耗流水         │
│                      │         │                      │
│  Order.cancelOrder() │──②──→  │  回滚库存（如已扣减）   │
│                      │         │  - 恢复半成品库存       │
│                      │         │  - 记录回滚流水         │
│                      │         │                      │
│  Order.createOrder() │──③──→  │  检查库存（可选）       │
│                      │         │  - 告警但允许下单       │
│                      │         │  - 不阻断营业           │
└──────────────────────┘         └──────────────────────┘
```

### 4.3 对接实现方式

restaurant 模块通过 **Feign 调用** 库存系统（库存系统作为独立微服务或 MES wm 扩展）：

```java
// restaurant 模块中
@Resource
private StockApi stockApi;  // Feign 接口

// KDS 完成出餐后
public void onKdsFinishItem(Long orderItemId) {
    // ... KDS 自身逻辑 ...
    // 扣减库存
    stockApi.deductStock(new DeductStockReq()
        .setSkuId(orderItem.getSkuId())
        .setQuantity(orderItem.getQuantity())
        .setStoreId(order.getStoreId())
        .setOrderNo(order.getOrderNo())
    );
}
```

### 4.4 初期策略

M2 阶段库存数据需要时间积累才能准确。因此：

- **初期不阻断下单**：库存不足时告警但不下架菜品
- **初期允许负库存**：等盘点体系跑通后再收紧
- **初期不做预占**：KDS 完成时才扣减，不做下单预占
- **退单自动回滚**：`cancelOrder` 触发库存回滚

## 7. 工程级要求清单

按《02-工程级标准 V1》逐条对照：

- [ ] **操作日志**：所有写操作 100% 加 @OperateLog，金额/状态变更记录 before/after
- [ ] **数据完整性**：删除用 @TableLogic，关键修改（价格、库存调整）有 history 表
- [ ] **异常处理**：业务异常用 ErrorCode + ServiceException，第三方调用（如对接 restaurant 模块）加超时重试
- [ ] **数据校验**：入参 @Valid，业务校验在 Service 层，金额用 BigDecimal
- [ ] **不可篡改**：库存调整必须走 4 种合法途径（盘点/调拨/损耗/报废），不能直接修改 stock_balance
- [ ] **并发安全**：出餐扣减用乐观锁（复用 MES 已有的 CAS 机制），采购入库考虑幂等
- [ ] **性能**：库存余额查询加索引（warehouse_id + material_id + batch_id），流水查询分页+时间倒序
- [ ] **多租户**：所有表继承 TenantBaseDO，tenant_id 必填
- [ ] **单元测试**：核心 Service（入库、出库、扣减、盘点差异处理）70%+ 覆盖
- [ ] **操作人**：所有写操作记录 creator/updater + create_time/update_time
- [ ] **时间精度**：所有时间字段用 LocalDateTime，精确到秒

## 8. 异常场景清单

| # | 异常场景 | 影响 | 处理策略 |
|---|---------|------|---------|
| 1 | 出餐扣减时库存不足 | 扣减失败，但不应阻断出餐 | 告警 + 允许负库存 + 标记异常，事后盘点修正 |
| 2 | 并发扣减同一 SKU | 库存数不一致 | 乐观锁（CAS），失败自动重试 3 次 |
| 3 | 网络断开导致扣减未执行 | 出餐已完成但库存未扣 | KDS 本地缓存待扣减记录，网络恢复后补扣 |
| 4 | 采购入库数量与采购单不符 | 库存数据不准确 | 按实际验收数量入库，记录差异，标记采购单"部分入库" |
| 5 | 验收时发现质量问题 | 不合格原料入库会污染库存 | 拒收 + 生成退货单 + 拍照留证 |
| 6 | 半成品制作损耗异常偏高 | 可能存在操作问题或偷盗 | 自动标记 + 通知店长审查 |
| 7 | 盘点差异超过阈值 | 库存数据可信度下降 | 必须店长审核 + 强制记录原因，不能直接过 |
| 8 | 保质期到期未处理 | 过期原料可能被使用 | 到期前 N 天自动预警 → 到期当天自动生成损耗单 |
| 9 | 人为误操作（录错数量/选错物料） | 库存不准确 | 通过盘点发现 + 库存调整留痕（不可直接修改） |
| 10 | 数据库故障导致库存写失败 | 库存与实际不符 | 事务回滚 + 告警 + 人工介入 |
| 11 | 门店间调拨在途库存 | 调出方已减、调入方未加 | 调拨单有"在途"状态，调入方收货确认后才完成 |
| 12 | 同一采购单重复入库 | 库存重复增加 | 采购单号 + 入库单号唯一约束，幂等校验 |
